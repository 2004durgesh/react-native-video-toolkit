---
title: 'VideoSurface'
description: A thin wrapper around react-native-video that integrates with the toolkit's context and hooks.
---

## Usage

```tsx
import { VideoSurface } from 'react-native-video-toolkit';

export function CustomSurfaceExample() {
  return (
    <VideoSurface
      source={{ uri: 'https://example.com/video.mp4' }}
      resizeMode="cover"
      onEnd={() => console.log('Playback finished')}
    />
  );
}
```

---

## Props

All props from [`react-native-video`](https://github.com/react-native-video/react-native-video#props) are supported.

| Prop                | Type                        | Required | Default         | Description                                                                                                            |
| ------------------- | --------------------------- | -------- | --------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `source`            | `ReactVideoProps['source']` | Yes      | –               | Video source (`uri`, local file, or require).                                                                          |
| `style`             | `StyleProp<ViewStyle>`      | No       | –               | Additional style applied to the `<Video>` surface.                                                                     |
| `testID`            | `string`                    | No       | `video-surface` | Identifies the surface in end-to-end tests. See [Testing](/docs/testing).                                              |
| `customAudioTracks` | `AudioTrack[]`              | No       | –               | Audio tracks to list instead of the source's own. Passing them turns custom audio tracks on.                           |
| `customVideoTracks` | `CustomVideoTrack[]`        | No       | –               | Qualities to list instead of the source's own, each with a `label` to show. Passing them turns custom video tracks on. |
| `...rest`           | `ReactVideoProps`           | No       | –               | Any other props from `react-native-video` are passed through.                                                          |

---

<Callout type="info">
**Events**

These events are **already handled internally** and connected to the global store:

- **`onLoad`** → sets duration, clears buffering, deduplicates tracks, and picks tracks: subtitles in the device's language, then the stream's default, then English, then the first track.
- **`onProgress`** → updates current time
- **`onBuffer`** → updates buffering state
- **`onError`** → dispatches an error message into state
- **`onEnd`** → stops playback, seeks to `0`, and shows controls
- **`onLayout`** → updates player layout in state

You can pass your own handlers for these events too. They run after the toolkit's and can't replace them, so your UI stays in sync.

</Callout>

---

<Callout type="info">
**Layout & Fullscreen**

- Automatically adapts when `fullscreen` is toggled in the global store.
- Uses a `16:9` aspect ratio by default in normal mode.
- In fullscreen, expands to `Dimensions.get('window')`.

</Callout>

---

<Callout type="warn">

- Typically, you **don't use `VideoSurface` directly** — it's already included inside `VideoPlayer`.
- Import it only if you want to **replace or deeply customize** the rendering of the video element (e.g., special resize modes, advanced performance tuning).

</Callout>

## Players without `VideoPlayer`

A player built from `VideoSurface` and your own controls needs a `VideoProvider` above it, like any player. It also leaves out three things that `VideoPlayer` does:

- **Subtitles.** The toolkit draws subtitle files itself, and `VideoSurface` never gives them to the native player. Render `<VideoPlayer.Captions />` over the video to show them.
- **Leaving fullscreen with Esc or Android's back button.** Only `VideoPlayer` listens for them.
- **Fullscreen on the web.** The browser fullscreens the element around `VideoPlayer`'s video, so without one it can't find the player.

To keep all three, build your layout inside `VideoPlayer` instead, and pass gesture handlers through its [`gestureProps`](../../../customization#gestures).
